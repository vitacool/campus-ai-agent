# 架构说明

## 数据流

```text
用户问题
  -> 意图识别与工具路由
  -> 轻量 RAG 检索
  -> 可选大模型生成
  -> 回答与来源返回
  -> SQLite 记录日志
  -> 用户反馈沉淀
```

## 模块说明

- `KnowledgeAgent.pick_tool`：根据问题关键词路由到通知查询、部门查询、报修助手、教务助手或通用问答。
- `KnowledgeAgent.retrieve`：对问题和知识库进行 token 匹配，结合关键词、标题命中和文档长度计算得分。
- `call_llm`：在配置 API Key 后调用 OpenAI 兼容接口；调用失败时自动回退本地回答。
- `chat_logs`：记录问题、回答、工具、来源、耗时和是否使用模型。
- `feedback`：记录用户对回答的正负反馈。

## 为什么保留零依赖实现

项目面向实习岗位展示，优先保证克隆后可以直接运行和验证。后续如果需要生产化，可以将当前 HTTP Server 替换为 FastAPI，并保留现有 Agent、检索和存储逻辑。

## 后续生产化路径

1. 使用 FastAPI 拆分路由、服务层和数据访问层。
2. 将 `knowledge.json` 替换为 MySQL 知识库表。
3. 将关键词检索替换为向量检索，并保留关键词召回作为 fallback。
4. 将用户反馈转为知识库优化和 prompt 优化流程。
5. 增加鉴权、限流、日志追踪和部署脚本。
